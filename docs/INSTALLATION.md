# Установка и проверка на трансляции

## Подготовка оверлея

1. Авторизуйтесь в StreamElements под аккаунтом канала Twitch. Создайте оверлей 1920×1080 и добавьте Custom Widget.
2. Задайте самому Custom Widget размер 1920×1080 и положение 0,0. Он имеет прозрачный фон; плашка располагается внутри его области.
3. Откройте редактор и вставьте содержимое `widget/HTML.html`, `CSS.css`, `JS.js`, `FIELDS.json` в HTML, CSS, JS, FIELDS. Удалите демонстрационный код из вкладок.
4. В DATA при первой установке вставьте `DATA.json`. Не помещайте туда snapshot пользователей: DATA — значения пользовательских полей. Если DATA недоступна, значения уже заданы в FIELDS.
5. Сохраните изменения. Выберите имя хранилища из латинских букв и цифр, например `MyChannelChatThanks`. Оно должно отличаться от других независимых виджетов того же аккаунта.
6. Для теста оставьте OBS-источник закрытым: одновременно активный редактор и источник могут конфликтовать.

## Быстрый тест в StreamElements

1. Включите «Изолированный тест», задайте «Порог награды в тесте» 10 секунд и «Число сообщений» 5. Сохраните/перезагрузите виджет.
2. Нажмите «Создать сообщения тестового зрителя». Запись создаётся только в тестовом пространстве. Реальный чат в этом режиме игнорируется.
3. Благодарность появляется после порога при ближайшей проверке (10–30 секунд). Она не должна появляться раньше порога.
4. Нажмите «Показать тестовую анимацию» для немедленной проверки внешнего вида. Эта кнопка не создаёт зрителя и не помечает реальную награду; допускается и в обычном режиме.
5. После окончания анимации обновите редактор, снова нажмите «Создать сообщения» и подождите: повторной автоматической награды в той же тестовой сессии быть не должно при выключенных повторах.
6. Нажмите сброс сессии, дождитесь перезагрузки и повторите проверку. Отключите тестовый режим и сохраните. Боевой ключ не менялся.

Порог и число сообщений независимы: если `testMessages` меньше `minMessages`, награда не появится. Повторное нажатие кнопки добавляет сообщения тому же синтетическому зрителю. Тестовая кнопка событий работает через документированный `widget-button`, поле берётся из `event.field`.

## Добавление в OBS Studio

1. Скопируйте URL оверлея из StreamElements. Держите его в секрете.
2. В OBS: Источники → «+» → Браузер → новый источник. Вставьте URL, ширину 1920 и высоту 1080. Если используется другая базовая сцена, согласуйте размеры оверлея и источника.
3. При наличии параметра задайте 60 FPS. Не задавайте непрозрачный фон через пользовательский CSS. Размер плашки меняйте в FIELDS.
4. Выключите остановку невидимого источника и обновление при активации сцены, чтобы учёт продолжался при переключениях.
5. В остальных сценах используйте «Добавить существующий» и этот же источник. Не создавайте независимые копии с тем же URL.
6. Закройте редактор и дополнительные вкладки с этим оверлеем. Оставьте один активный экземпляр. Если конфликт уже обнаружен, перезагрузите оставшийся.

«Наблюдатель» — режим без учёта и выдачи наград. Он не является синхронизированным зеркалом уведомлений. Роль задаётся в FIELDS, поэтому изменение в одном и том же сохранённом виджете распространится и на другие его загрузки.

## Звук

Выберите файл через поле `sound-input`, включите звук и установите громкость. Пустой файл означает тихую анимацию. Проигрываются только HTTP(S)-адреса. Ошибка `Audio.play()` не останавливает благодарности. При необходимости включите управление звуком через OBS в настройках Browser Source и проверьте микшер/мониторинг. В браузере звук может требовать разрешения; фактическая политика OBS зависит от версии.

## Проверка сохранения

1. С единственным экземпляром включите сохранение, отключите тестовый режим. Для короткой проверки можно поставить боевой порог 1 минуту (после проверки верните 60).
2. Отправьте 4 сообщения от одного Twitch-пользователя. Подождите интервал сохранения плюс до 5 секунд на подтверждение.
3. Обновите Browser Source. После наступления порога отправьте пятое сообщение: должна появиться награда, без необходимости заново отправлять первые четыре.
4. Дождитесь записи, перезапустите OBS, отправьте ещё сообщение. Повторной награды быть не должно.
5. Для отдельной проверки отрицательного случая подождите больше окна недавней активности без сообщений. Просроченный зритель не награждается.
6. Проверьте журнал: предупреждения о резервном режиме означают, что серверное восстановление не подтверждено.

Время с первого сообщения продолжается по календарным часам после перезапуска, но сообщения во время выключенного виджета не учитываются. Общая неактивность может сбросить сессию; срок хранения может сделать snapshot недействительным.

## Сброс перед новым стримом

Достоверного Twitch-события начала эфира здесь нет. Выберите:

- «После общей неактивности чата»: новая сессия при следующей проверке/сообщении после заданного простоя; по умолчанию 6 часов.
- «Только вручную»: перед эфиром задайте новый `resetToken`, сохраните и перезагрузите источник, либо используйте кнопку сброса в единственном активном редакторе.

Во время сброса старая анимация прекращается, незавершённая запись дожидается окончания, затем записывается пустая сессия. При отключённом сохранении сброс действует только в памяти; включите сохранение, чтобы заменить и постоянный снимок. Кнопка полной очистки заменяет данные текущего пространства имён пустым снимком; физическое удаление ключей не поддерживается SE_API.

## Ручная проверка перед эфиром

Пройдите [контрольный список](VALIDATION.md). Проверка в настоящем StreamElements и OBS нужна для подтверждения доставки событий, серверной записи, звука и производительности на вашем компьютере. Официальные API не предоставляют транзакций, поэтому параллельные активные экземпляры не поддерживаются даже после успешной проверки.
