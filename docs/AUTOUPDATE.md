# Автоматическое обновление JavaScript из GitHub

## Однократная настройка

1. Оставьте HTML, CSS, FIELDS и DATA установленными по обычной инструкции.
2. Откройте [AUTOUPDATE.js](https://github.com/xel92/widget-aktivnost/blob/main/widget/AUTOUPDATE.js) и нажмите **Copy raw file**.
3. Во вкладке **JS** Custom Widget полностью замените прежнее содержимое этим загрузчиком. Не вставляйте вместе `JS.js` и `AUTOUPDATE.js`: выбирается один из двух способов.
4. Сохраните виджет и обновите оверлей/Browser Source.
5. Нажмите «Показать тестовую анимацию». Проверьте, что она появилась, а в консоли есть `[ChatThanks updater] JavaScript загружен из GitHub`.

Загрузчик обращается только к публичному адресу `https://raw.githubusercontent.com/xel92/widget-aktivnost/main/widget/JS.js`. Токен GitHub не нужен. Репозиторий должен оставаться публичным. URL оверлея и события чата на GitHub не отправляются; запрос содержит только адрес исходника и время для обхода кэша.

## Как приходят обновления

При каждом запуске загрузчик получает свежий `widget/JS.js` из ветки `main`. Пока виджет открыт, проверка выполняется раз в **5 минут**. Браузерные таймеры могут замедляться в фоне. Добавление кода в репозиторий само по себе не обновляет выключенный источник: он получит файл при следующем запуске.

Если текст JS изменился, загрузчик ждёт, пока завершатся текущая анимация, пауза и очередь. Проверка возможности установки повторяется каждые 2 секунды. При непрерывно заполненной очереди обновление откладывается. Далее сохраняется прогресс, делается снимок в памяти и запускается новый код. Действующая сессия, счётчики, выданные награды и настройки сохраняются. Передача в памяти работает даже с отключённым постоянным сохранением — это не заменяет хранение между закрытиями браузера.

Сообщения и события кнопок во время загрузки/замены временно буферизуются (до 5000 событий). Подтверждения SE_API.store не блокируются. Событие `onWidgetLoad`, пришедшее раньше удалённого JS, повторяется для нового экземпляра с исходными FIELDS. Это важно: обычная асинхронная вставка внешнего script без такого механизма могла бы пропустить инициализацию виджета.

Удалённый файл исполняется через стандартный `script` с Blob URL; `eval` и GitHub API с токенами не используются. Последняя успешно запущенная версия сохраняется в localStorage. Если GitHub недоступен, действующий виджет продолжает работу; после перезагрузки используется локальная копия, если она есть. При первой установке без сети и без копии код загрузить невозможно — будет предупреждение в консоли. При запрете localStorage офлайн-копия недоступна.

Новая версия с ошибкой запуска отклоняется; если старый runtime ещё действует, он возобновляется, иначе загрузчик пытается вернуть предыдущий рабочий код. Такой откат не является защитой от любых логических ошибок: новую версию нужно проверять тестами перед публикацией.

## Какие файлы обновляются

Автоматически обновляется **только `widget/JS.js`**. HTML, CSS, FIELDS, DATA и сам установленный `AUTOUPDATE.js` остаются во вкладках StreamElements.

Совместимые изменения логики публикуются с маркером `/* CHAT_THANKS_API:1 */` в начале `JS.js`. Если изменение требует другого HTML, CSS или FIELDS, разработчик должен изменить маркер протокола. Старый загрузчик откажется устанавливать несовместимый код и оставит текущую версию. После этого новые вкладки и загрузчик устанавливаются вручную. Маркер — договорённость о совместимости, а не автоматический анализ кода.

Загрузка кода по ветке `main` означает, что после публикации совместимого изменения оно попадёт на работающий оверлей без отдельного подтверждения. Не публикуйте в эту ветку непроверенные изменения. Чтобы временно зафиксировать версию, замените `main` в константе `SOURCE` загрузчика полным SHA нужного коммита и сохраните JS в StreamElements. Для отключения автообновления установите обычный `widget/JS.js` вместо загрузчика.

## Проверка и ограничения

Автообновление проверено в Chromium с перехватом запросов GitHub: поздняя инициализация, ранние сообщения, передача состояния, ожидание анимации, отказ сети, офлайн-запуск, ошибочная версия, передача в памяти без постоянного хранилища. Команда при работающем локальном HTTP-сервере:

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run test:autoupdate
```

Первое получение настоящего публичного исходника следует проверить в вашем StreamElements. Если политика CSP редактора/Browser Source блокирует `fetch` к raw.githubusercontent.com или исполнение Blob URL, загрузчик сообщит об этом в консоли. Не ослабляйте защиту браузера: используйте обычную установку `JS.js` из репозитория. Доставка через внешнюю сеть и работоспособность конкретной версии OBS требуют ручной проверки.

Остальные ограничения виджета сохраняются: один активный экземпляр, время с первого сообщения вместо подтверждённого просмотра, ручной сброс/тайм-аут сессии и ограниченные гарантии постоянного хранилища.
