# Автоматическое обновление HTML, CSS и JavaScript из GitHub

## Однократная настройка или переход со старого загрузчика

1. Оставьте существующие **FIELDS и DATA**, а также собственные настройки без изменений. Новый загрузчик их не заменяет.
2. Откройте [AUTOUPDATE.js](https://github.com/xel92/widget-aktivnost/blob/main/widget/AUTOUPDATE.js) и нажмите **Copy raw file**.
3. Во вкладке **JS** Custom Widget полностью замените прежнее содержимое этим загрузчиком. Не вставляйте вместе `JS.js` и `AUTOUPDATE.js`.
4. Очистите вкладки **HTML и CSS**. Загрузчик сам получает их содержимое из репозитория. Особенно важно очистить старый CSS, чтобы его правила не влияли на будущие версии оформления.
5. Сохраните все изменения, обновите оверлей/Browser Source и подождите загрузки. Размер Custom Widget оставьте на весь оверлей, например 1920×1080.
6. Нажмите «Показать тестовую анимацию». В консоли успешную загрузку подтверждает `[ChatThanks updater] HTML, CSS и JS обновлены вместе: …`.

Старый загрузчик, который обновлял только JS, **сам себя не заменит**. Новый `AUTOUPDATE.js` нужно один раз скопировать вручную. Прогресс и настройки сохраняются при прежнем `storageNamespace`, `resetToken` и действующей сессии; не вставляйте начальный DATA повторно и не нажимайте сброс ради обновления.

## Как приходят будущие изменения

При запуске и затем раз в **5 минут** загрузчик проверяет ветку `main` репозитория `xel92/widget-aktivnost`. Браузерные таймеры в фоне могут замедляться. Изменения получает работающий источник; выключенный — при следующем запуске.

Сначала GitHub сообщает SHA текущего коммита. Затем `widget/HTML.html`, `widget/CSS.css` и `widget/JS.js` скачиваются **по этому же SHA**, а не независимо из меняющейся ветки. Если `main` изменится во время скачивания, все три файла всё равно относятся к одной версии. Проверяются ответы, размеры, маркер совместимости JS и обязательные элементы HTML. При ошибке одного запроса весь новый комплект отклоняется до изменения страницы.

Если SHA не изменился, файлы повторно не скачиваются. Если коммит изменился, а содержимое трёх файлов осталось прежним, повторного запуска виджета нет. Правка только CSS или только HTML также распознаётся и применяется — менять JS для этого не требуется.

Для установки загрузчик ждёт, пока завершатся анимация, пауза и очередь благодарностей. Возможность установки проверяется каждые 2 секунды. Постоянно заполненная очередь откладывает обновление. Далее завершается запись, создаётся снимок прогресса в памяти, заменяются HTML/CSS и запускается новый JS с прежними FIELDS. Сессия, счётчики и награды передаются новому runtime. Передача в памяти работает и при выключенном постоянном сохранении, но не заменяет хранение между закрытиями браузера.

Сообщения и кнопки во время скачивания первоначального комплекта и самой замены буферизуются, максимум 5000 событий. Подтверждения SE_API.store не блокируются. Настоящий `onWidgetLoad` сохраняется и повторяется для нового кода; без него новый runtime не запускается с выдуманными настройками.

## Откат и работа без сети

Предыдущие узлы HTML и CSS сохраняются до успешной инициализации нового JS. Если новый скрипт не запустился или не подтвердил готовность, возвращаются старые узлы, прежний JS и снимок прогресса. Если ошибка случилась до остановки старого runtime, он просто возобновляется. Это защита от ошибок запуска, а не автоматическое обнаружение всех логических ошибок: изменения нужно тестировать до публикации.

В localStorage сохраняется **полный успешно запущенный комплект**: HTML, CSS, JS и SHA. При недоступности GitHub текущий виджет продолжает работать. После перезапуска без сети загружается последняя рабочая локальная копия сразу с оформлением. Неполные и некорректные кеши не принимаются. Локальный кеш старого JS-only загрузчика не считается полным комплектом: первый запуск нового загрузчика должен пройти с сетью.

При первой установке без сети и без полного кеша загрузить виджет невозможно. Если localStorage запрещён или переполнен, текущая версия работает в памяти, но офлайн-запуск не гарантируется. При запросе теста незагруженный виджет показывает видимое сообщение с причиной.

## Что остаётся в StreamElements

- **FIELDS и DATA** не обновляются автоматически. Ваши значения полей сохраняются и продолжают задавать цвета, размеры, тексты и поведение поверх исходных значений новой версии.
- Сам установленный **AUTOUPDATE.js** не заменяется удалённым кодом. Обычно его менять не нужно; смена протокола может потребовать однократной ручной замены.
- Размер, положение и видимость самого Custom Widget в редакторе задаются в StreamElements. Загрузчик не меняет размер его контейнера.

Новые элементы настроек требуют обновления FIELDS вручную. Изменения оформления и логики, использующие существующие поля, будут приходить автоматически.

## Правила для будущих правок репозитория

Публикуйте связанные изменения HTML/CSS/JS **одним коммитом**: каждый отдельный коммит ветки main может быть получен работающим оверлеем. Не публикуйте промежуточные несовместимые состояния.

Сохраните контракт разметки: один `#thanks-root` со всем содержимым; внутри по одному `#thanks-card`, `#thanks-title`, `#thanks-name`, `#thanks-text`, `#thanks-minutes`, `#thanks-messages`, а также `.thanks-particles` внутри карточки. Визуальный порядок, классы, SVG, размеры и правила CSS можно менять. Скрипты, `<style>`, iframe и ссылки на внешние стили внутри HTML не поддерживаются: CSS/JS передаются отдельными файлами.

Маркер `/* CHAT_THANKS_API:1 */` в начале JS теперь обозначает совместимость с установленными FIELDS и протоколом загрузчика. Правки HTML/CSS в рамках указанного контракта **не требуют** его изменения. Если нужны новые обязательные поля или другой контракт, разработчик меняет маркер; старый загрузчик оставляет текущую версию и сообщает о несовместимости. Маркер — договорённость разработчика, а не автоматический анализ всего кода.

Для отключения автообновления установите **все три файла** обычным способом: HTML.html во вкладку HTML, CSS.css в CSS и JS.js в JS. Одного JS.js при пустом HTML/CSS недостаточно.

## Сеть и проверка

Используются публичные адреса GitHub API для SHA и raw.githubusercontent.com для файлов. Токен не нужен, репозиторий должен оставаться публичным. Ключи StreamElements, URL оверлея и чат не отправляются в этих запросах. При одном экземпляре и интервале 5 минут получается примерно 12 проверок GitHub API в час; у публичного API есть лимиты, общие для исходящего IP. Ошибка HTTP 403/429 оставляет рабочую версию/кеш до следующей успешной проверки.

Новый HTML устанавливается как доверенная разметка из вашего репозитория; текст зрителей по-прежнему выводится через textContent в основном JS. Новый CSS устанавливается отдельным style, JS — через Blob script без eval. CSP конкретного StreamElements/OBS должна разрешать эти операции и сетевые адреса. Политика не ослабляется автоматически. Если операции запрещены, используйте ручной вариант трёх вкладок.

Проверка в Chromium с эмуляцией GitHub:

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run test:autoupdate
```

Покрыты первоначально пустые HTML/CSS, ранние сообщения, единый SHA при смене main, правка только CSS, сохранение FIELDS и сессии, ожидание анимации, ошибка одного файла, повреждённый HTML, откат всего комплекта после остановки старого runtime, офлайн-запуск и отключённое постоянное сохранение. Установка в авторизованном StreamElements и конкретном OBS остаётся ручной проверкой. Остальные ограничения основного виджета, включая один активный экземпляр, сохраняются.
