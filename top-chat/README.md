# Топ чата — отдельный виджет

Статус: проектирование. Не установлен в StreamElements.
Название текущего персонального виджета: «Плашки рангов».
Название нового виджета: «Топ чата».

## Границы проекта

- Персональные плашки остаются в widget/. Их зафиксированная версия: тег rank-cards-v1.0.0, коммит 67fb229d8864b29718a68ba5f7d56c7e97f5c444.
- Новый виджет разрабатывается в top-chat/, ветка feature/top-chat.
- Отдельный Custom Widget в StreamElements, свои HTML/CSS/JS/FIELDS/DATA и загрузчик.
- Изменения top-chat не должны менять widget/ или его загрузчик.
- Изменения общей статистики сначала описать пользователю, включая влияние на оба виджета.
- Визуальные изменения показывать на превью и публиковать после одобрения.
- В рабочем виджете есть незакрытое сообщение пользователя: ни тестовые кнопки, ни закрепление не показывают плашку в StreamElements/OBS. Локальные проверки проходят; предложена замена AUTOUPDATE.js, результат пользователем ещё не подтверждён. Не считать проблему устранённой.

## Первая версия: предложение для превью

- Список участников с аватаркой, ником, количеством сообщений, местом и достигнутым рангом.
- Появление раз в 5 минут; интервал настраивается.
- Предлагаемые значения: топ-5, показ 15 секунд. Количество строк и длительность настраиваются.
- Дунхуа-оформление, согласованное по стилю с «Плашками рангов».
- Кнопки «Показать тест», «Закрепить для настройки», «Скрыть».
- Равное число сообщений даёт одинаковое место: 1, 1, 3; для стабильного порядка при равенстве использовать постоянный идентификатор.
- При малом количестве зрителей показывать только существующих; пустой список не выдавать за реальные данные.
- Тестовые данные явно отделены от настоящих.

## Статистика и сессии

План: один источник считает сообщения и выдаёт ранги, новый виджет читает статистику.
Нельзя запускать второго писателя в существующее хранилище.
Перед реализацией проверить доступность общего SE_API.store между двумя Custom Widget в одном оверлее.
Если область хранилища не общая, предложить иной канал синхронизации до изменения рабочего виджета.
Первый прототип интерфейса работает на явно обозначенных демонстрационных данных.

Место — по количеству сообщений среди учитываемых участников текущей сессии.
Ранг — уже достигнутый/выданный ранг из статистики; не вычислять независимо по фиксированному времени, поскольку пороги индивидуальны с разбросом.
Сброс общей сессии должен сбрасывать оба представления.
Старт нового эфира сейчас автоматически не определяется: ручной сброс или 6 часов общей неактивности.
Не называть время с первого сообщения подтверждённым временем просмотра.
Нужно показывать или корректно обрабатывать устаревшую/недоступную статистику.
