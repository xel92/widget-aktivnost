# First Message и проверенные источники

Проверено по документации 10 ноября 2026 года.

- StreamElements: https://docs.streamelements.com/overlays/events — Twitch message
  использует event.data, включая text, nick, userId, msgId и tags. В опубликованном
  Twitch-примере нет обещания передачи first-msg. YouTube имеет другой payload;
  этот виджет предназначен для Twitch и не переносит YouTube-поля в Twitch-логику.
- Twitch: https://dev.twitch.tv/docs/chat/irc/ — официальные примеры PRIVMSG
  содержат first-msg=1 и first-msg=0. В Shared Chat учитывать исходную комнату.
- EventSub: https://dev.twitch.tv/docs/chat/irc-migration/ — формат отличается от
  IRC; нельзя просто приравнять любое сообщение EventSub к первому.

В коде допускаются только строки "1"/"0" и числа 1/0 в tags['first-msg'].
Иные значения и отсутствие признака — unknown. Отсутствие прежней записи о
зрителе ничего не доказывает. Неподтверждённое сообщение не заменяет подтверждённое.
При отсутствии события показан текст «Пока никто не написал своё первое сообщение»;
диагностика отдельно объясняет неизвестность признака. Это не доказательство,
что в канале действительно не было новых зрителей.

Текст показывается через textContent, с переносами и без сокращений. Технический
предел входного First Message — 65536 UTF-16 единиц (значительно больше обычного
Twitch-сообщения); более длинное повреждённое событие отклоняется целиком, а не
молча обрезается. Полная история не хранится. После удаления сообщения модератором
нижний блок очищается; назад к предыдущему сообщению не откатывается.

## Реальная проверка на канале

1. Выключите изолированный тест и демонстрационные данные. Включите диагностику
   first-msg или нажмите «Показать диагностику».
2. Отправьте обычное сообщение из аккаунта, который уже общался в этом канале.
   Проверьте увеличение received и ordinary/unknown; First Message не должен
   заменяться этим текстом.
3. Попросите участника, который никогда раньше не писал именно в вашем канале,
   отправить первое сообщение. Не считайте новый аккаунт или новый эфир достаточным
   доказательством без проверки флага.
4. Должен увеличиться confirmed; внизу появятся его ник и полный текст.
5. Дождитесь интервала сохранения, перезагрузите Browser Source и проверьте
   восстановление текста. Затем отправьте обычное сообщение и убедитесь, что
   оно не заменяет First Message.
6. Если всё приходит как unknown, StreamElements не передаёт флаг в этом окружении.
   Локальные тесты с tags['first-msg']='1' не доказывают боевую поддержку.

Диагностика содержит только счётчики и состояния. Не публикуйте целый onWidgetLoad:
в нём могут быть токены. Виджет сам их не логирует.

## Возможное расширение

Можно добавить серверный/Streamer.bot адаптер, который принимает подтверждённый
признак из исходного Twitch-события и передаёт нормализованные данные. В этой
версии такой сервис не развёрнут: его аутентификацию, доступ из OBS и контракт
нужно согласовать отдельно. Не включён небезопасный открытый WebSocket и не
вставляются приватные OAuth-токены в Browser Source.

## Аватары

В документированном Twitch payload StreamElements нет гарантированного avatar URL.
Twitch Get Users возвращает profile_image_url, но требует app/user access token:
https://dev.twitch.tv/docs/api/get-started
https://dev.twitch.tv/docs/api/reference#get-users

Реализован отдельный документированный публичный провайдер DecAPI:
https://documentation.decapi.dev/twitch/avatar/
https://documentation.decapi.dev/cached-endpoints/

Ему передаётся только публичный логин. Авторизация не требуется для этого
публичного endpoint DecAPI; это не утверждение о Twitch Helix. Принимается только
HTTPS на static-cdn.jtvnw.net/jtv_user_pictures/. Кеш до 100 записей: успех 15 минут,
ошибка 5 минут; у провайдера собственный кеш до 30 минут. Общий бюджет изображения
3,5 секунды, при ошибке встроенная заглушка. Картинки не блокируют показ и не
сохраняются в серверном прогрессе. В FIELDS можно выбрать только заглушку.
Для инфраструктуры без стороннего провайдера потребуется собственный backend
с серверным OAuth и кешем; секреты не должны попадать в публичные файлы.
